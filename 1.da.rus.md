# 4. Введение

## 4.1. Почему анализ данных важен?

Представим интернет-магазин.

За месяц он получил:

* 100 000 заказов;
* 350 000 посещений сайта;
* 20 000 отмен;
* 50 000 различных товаров;
* миллионы событий пользователей.

У компании возникает вопрос:

> **Почему продажи в этом месяце снизились на 8%?**

Ответ нельзя получить простым просмотром таблицы.

Необходимо:

1. собрать данные;
2. проверить их качество;
3. объединить данные из разных источников;
4. очистить их;
5. исследовать;
6. найти закономерности;
7. визуализировать результаты;
8. сформулировать вывод;
9. предложить решение.

Именно здесь появляется **Data Analysis**.

---

## 4.2. Главное назначение Data Analysis

Анализ данных можно представить как переход:

**сырые данные → информация → знания → решение**

Например:

> Продажи = 10 000 заказов

Это просто данные.

После анализа:

> В понедельник количество заказов на 35% меньше среднего.

Это уже информация.

После дополнительного исследования:

> Причина — существенное снижение рекламного трафика по понедельникам.

Это аналитический вывод.

И наконец:

> Следует перераспределить рекламный бюджет на понедельники.

Это уже **решение**.

# 5. Что такое Data Analysis?

## 5.1. Определение

**Data Analysis — это систематический процесс исследования, преобразования и интерпретации данных с целью получения полезной информации и поддержки принятия решений.**

Важно понимать:

> **Data Analysis — это не просто построение графиков.**

График является инструментом.

Цель анализа — **ответить на вопрос или решить проблему**.

---

## 5.2. Пример

Допустим, университет хранит данные:

| Student | Age | Faculty   | GPA | Attendance |
| ------- | --: | --------- | --: | ---------: |
| Ali     |  20 | CS        | 3.8 |         94 |
| Sara    |  21 | CS        | 3.2 |         72 |
| John    |  20 | Economics | 3.6 |         88 |
| Mary    |  22 | CS        | 2.9 |         65 |

Можно спросить:

> Есть ли связь между посещаемостью и успеваемостью?

Тогда Data Analyst:

1. получает данные;
2. проверяет пропуски;
3. исследует распределения;
4. рассчитывает статистики;
5. строит графики;
6. анализирует взаимосвязь;
7. формулирует вывод.

# 7. Типичный процесс анализа данных

Практический процесс обычно выглядит следующим образом:

1. **Problem Definition** — формулировка проблемы.
2. **Data Collection** — сбор данных.
3. **Data Cleaning** — очистка.
4. **Data Preparation** — подготовка.
5. **Exploratory Data Analysis** — разведочный анализ.
6. **Visualization** — визуализация.
7. **Statistical Analysis** — статистический анализ.
8. **Interpretation** — интерпретация.
9. **Communication** — представление результатов.
10. **Decision** — принятие решения.

Важно: это не всегда строго линейный процесс. Аналитик часто возвращается назад.

Например, при анализе обнаруживается:

> "Нам не хватает данных за предыдущий год."

Следовательно, необходимо снова обратиться к этапу сбора данных.

# 8. Data Analyst, Data Scientist и Data Engineer

Это одна из наиболее важных тем для начинающего специалиста.

Три профессии часто путают.

---

## 8.1. Data Analyst

### Основной вопрос

> **Что произошло и почему?**

Data Analyst работает с существующими данными и пытается получить из них полезные выводы.

Типичные задачи:

* SQL-запросы;
* очистка данных;
* статистика;
* Excel;
* Python;
* визуализация;
* dashboards;
* отчёты;
* бизнес-аналитика.

IBM также описывает Data Analyst как специалиста, который прежде всего использует статистический анализ для ответа на конкретные бизнес-вопросы и получения практически полезных выводов. ([IBM][1])

---

## 8.2. Data Scientist

### Основной вопрос

> **Что может произойти в будущем и можем ли мы это предсказать?**

Data Scientist занимается более сложными аналитическими задачами.

Например:

> Какие клиенты с большой вероятностью перестанут пользоваться сервисом?

Для этого можно создать ML-модель.

Типичные направления:

* статистика;
* Machine Learning;
* predictive modeling;
* эксперименты;
* feature engineering;
* NLP;
* Computer Vision;
* прогнозирование.

По данным O*NET, среди задач Data Scientist присутствуют обработка больших наборов данных, визуализация, проверка моделей, работа с ML и выявление закономерностей. ([onetonline.org][2])

---

## 8.3. Data Engineer

### Основной вопрос

> **Как сделать так, чтобы необходимые данные вообще были доступны, качественны и надёжны?**

Data Engineer строит инфраструктуру данных:

* databases;
* data warehouses;
* data lakes;
* pipelines;
* ETL/ELT;
* streaming;
* orchestration;
* monitoring.

Google Cloud определяет работу Data Engineer через сбор, преобразование, хранение и предоставление данных, а также создание надёжной инфраструктуры обработки данных. ([Google Cloud][3])

---

## 10.3. Python объединяет несколько этапов

Например, один notebook может содержать:

```python
import pandas as pd
import matplotlib.pyplot as plt

df = pd.read_csv("sales.csv")

print(df.head())

print(df["sales"].mean())

df.plot(x="month", y="sales")

plt.show()
```

То есть в одном инструменте можно:

* загрузить данные;
* обработать их;
* вычислить статистики;
* построить график;

# 15. Что такое Kernel?

Одна из самых важных концепций Jupyter.

**Kernel — процесс, который выполняет код notebook.**

Например:

```python
x = 10
```

После выполнения переменная `x` существует в памяти kernel.

Следующая ячейка:

```python
print(x)
```

выведет:

```text
10
```

Но если kernel перезапустить:

```text
x
```

даст ошибку, потому что переменная была уничтожена.

---

## Типичная ошибка новичка

Студент видит:

```python
a = 10
```

затем:

```python
print(a)
```

Всё работает.

После этого он перезапускает kernel и запускает только вторую ячейку.

Получает:

```text
NameError: name 'a' is not defined
```

### Причина

Notebook хранит код на диске, но переменные находятся **в памяти kernel**.

# 35. Типичная ошибка

```python

```

Ошибка:

```text

```

Почему?

Потому что:

```text
"20" → str
5    → int
```

Python не выполняет такое сложение автоматически.

Исправление:

```python
age = int("20")

print(age + 5)
```

Результат:

```text
25
```

# 43. Почему Git особенно важен для notebooks?

Notebook содержит не только код, но и:

* output;
* metadata;
* результаты;
* текст;
* изображения.

Поэтому Git может показывать довольно сложные изменения `.ipynb`.

Практические рекомендации:

1. Не хранить огромные datasets непосредственно в Git.
2. Не загружать API keys и passwords.
3. Регулярно делать commits.
4. Давать понятные commit messages.
5. Документировать проект в `README.md`.
6. Для больших файлов использовать специализированные хранилища.

# 44. Безопасность: что нельзя отправлять в GitHub

Никогда не помещайте в публичный repository:

```text
API_KEY=...
PASSWORD=...
DATABASE_PASSWORD=...
SECRET_TOKEN=...
```

Особенно опасно:

```python
api_key = "sk-..."
```

Если такой файл попадёт в публичный GitHub repository, секрет может стать доступным другим людям.

Даже если потом удалить строку из текущей версии файла, она может остаться в Git history.

# 51. Типичные ошибки начинающего аналитика

## Ошибка 1. Сразу строить графики

Неправильно:

> "У меня есть CSV — давайте построим 20 графиков."

Правильнее:

> "Какой вопрос я пытаюсь решить?"

---

## Ошибка 2. Не проверять качество данных

Например:

```text
Age
20
21
22
999
19
```

Среднее значение будет искажено.

---

## Ошибка 3. Путать корреляцию и причинность

Если:

> продажи мороженого ↑
> количество купающихся ↑

это ещё не означает:

> мороженое вызывает купание.

Обе величины могут зависеть от третьего фактора:

> температуры.

---

## Ошибка 4. Игнорировать типы данных

Например:

```python
age = "20"
```

может выглядеть как число для человека, но для Python это строка.

---

## Ошибка 5. Не сохранять историю работы

Если каждый раз сохранять:

```text
analysis_final.ipynb
analysis_final2.ipynb
analysis_final_new.ipynb
analysis_final_new2.ipynb
```

это плохая замена системе контроля версий.

Используйте Git.

# 52. Итоги

1. **Data Analysis** превращает сырые данные в полезную информацию для принятия решений.
2. Аналитика начинается не с графика, а с **правильно сформулированного вопроса**.
3. Типичный процесс включает сбор, очистку, подготовку, исследование, визуализацию и интерпретацию.
4. **Data Analyst** в основном отвечает на вопросы о происходящем и помогает принимать решения.
5. **Data Scientist** занимается более сложным статистическим моделированием, прогнозированием и ML.
6. **Data Engineer** создаёт инфраструктуру, pipelines и системы, обеспечивающие доступность данных.
7. Python популярен благодаря простому синтаксису и огромной экосистеме.
8. **Google Colab** позволяет быстро начать работать с Python без сложной локальной настройки.
9. **JupyterLab** предоставляет полноценную интерактивную среду для notebooks и анализа.
10. **Git/GitHub** позволяют сохранять историю проекта и организовывать совместную работу.

# Что нужно запомнить

### 1. Data Analysis ≠ просто графики

Главная цель:

> **получить обоснованный ответ на вопрос.**

### 2. Три роли

> **Data Engineer → обеспечивает данные**

> **Data Analyst → анализирует данные**

> **Data Scientist → строит модели и прогнозы**

При этом границы между ролями могут пересекаться.

### 3. Python

Для начала Data Analysis необходимо постепенно освоить:

```text
Python
↓
NumPy
↓
pandas
↓
Matplotlib
↓
Statistics
↓
EDA
↓
Machine Learning
```

### 4. Notebook

Notebook объединяет:

> **код + результат + текст + визуализацию**

### 5. Git

Запомните базовую последовательность:

```bash
git add
git commit
git push
```

А для получения изменений:

```bash
git pull
```
